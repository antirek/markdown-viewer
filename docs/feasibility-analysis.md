# Анализ реализуемости: Markdown Viewer как web-app

**Дата:** 2026-08-21  
**ОС целевая:** Ubuntu 20.04  
**Концепция:** сайт → установка как PWA (web-app) → файлы `.md` на компьютере открываются в этом приложении только для просмотра (без редактирования).

---

## Вердикт

**Концепция реализуема**, но с важными оговорками по браузеру и по тому, как ОС назначает приложение по умолчанию.

| Часть идеи | Оценка |
|---|---|
| Просмотр `.md` в браузере | Тривиально |
| Установка сайта как «приложения» (PWA) | Реализуемо в Chromium-браузерах |
| Открытие локальных `.md` двойным кликом в этом web-app | Реализуемо через **File Handling API** (только Chromium desktop) |
| «Все `.md` сразу открываются сами» без настройки | **Нет** — пользователь (или ОС) должен выбрать приложение по умолчанию |
| Тот же сценарий во Firefox на Ubuntu 20.04 | **Не работает** для ключевой части (file handlers) |

Итог: путь «как браузер / как сайт → установили → смотрим markdown» **реалистичен**, если целевой браузер — **Chrome / Chromium / Edge**. Во Firefox идея «установили и файлы открываются» в нужном виде **пока не закрывается**.

---

## Что именно нужно от системы

Желаемый пользовательский путь:

1. Зайти на сайт.
2. Установить как web-app (PWA).
3. Двойной клик по `*.md` в файловом менеджере → открывается это приложение.
4. Файл только читается и рендерится; редактирования нет.

Технически это три независимых слоя:

1. **PWA-оболочка** — installable web app (manifest + service worker + HTTPS).
2. **Регистрация типа файлов** — `file_handlers` в web app manifest.
3. **Приём файла от ОС** — `window.launchQueue` + чтение `FileSystemFileHandle`.
4. **Рендер markdown** — любая JS-библиотека (markdown-it, marked, micromark и т.п.).

Просмотр markdown — самая простая часть. Главный риск — **интеграция с ОС через PWA**, а не парсер Markdown.

## Как это устроено в современных браузерах

### 1. Установка как приложения

Нужны:

- HTTPS (или `localhost` для разработки);
- `manifest.webmanifest` (`name`, `icons`, `start_url`, `display: "standalone"` / `"minimal-ui"`);
- service worker (для installability / offline).

После установки Chromium создаёт ярлык и `.desktop`-запись (на Linux обычно в `~/.local/share/applications/`), и приложение появляется отдельно от вкладки браузера.

### 2. Связка с `.md`

В манифесте объявляется обработчик:

```json
{
  "file_handlers": [
    {
      "action": "/",
      "accept": {
        "text/markdown": [".md", ".markdown"],
        "text/x-markdown": [".md"]
      },
      "launch_type": "single-client"
    }
  ]
}
```

После установки ОС видит PWA как кандидата в «Открыть с помощью…».

### 3. Получение файла внутри приложения

```js
if ('launchQueue' in window && 'files' in LaunchParams.prototype) {
  launchQueue.setConsumer(async (launchParams) => {
    for (const handle of launchParams.files) {
      const file = await handle.getFile();
      const text = await file.text();
      // renderMarkdown(text)
    }
  });
}
```

Это официальный механизм Chrome: [File Handling API](https://developer.chrome.com/docs/capabilities/web-apis/file-handling), [MDN: Associate files with your PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/How_to/Associate_files_with_your_PWA).

Практика уже есть у продуктов вроде Excalidraw и markdown-ридеров с PWA (например, mdread с `file_handlers` для `.md`).

## Поддержка браузеров (критично для концепции)

| Возможность | Chrome / Chromium / Edge (desktop) | Firefox | Примечание для Ubuntu |
|---|---|---|---|
| Установка PWA | Да | На Linux долго была слабой / через обходные пути; нативная поддержка развивается, но нестабильна относительно Chrome | На Ubuntu 20.04 «из коробки» часто Firefox |
| `file_handlers` + `launchQueue` | Да (примерно с Chrome 102+) | **Нет** | Ключ концепции |
| Чтение файла после открытия ОС | Да (с permission prompt) | — | Пользователь должен разрешить доступ |
| Drag-and-drop / «Открыть файл» внутри UI | Да | Да | Запасной путь без OS-association |

**Вывод по браузерам:** полная концепция = **Chromium-стек**. Firefox годится максимум как «открыл сайт → загрузил `.md` вручную / drag-and-drop», но не как системный просмотрщик по двойному клику.

На Ubuntu 20.04 это значит:

- либо явно ориентироваться на **Google Chrome / Chromium / Microsoft Edge**;
- либо честно сузить обещание продукта: «лучший опыт в Chrome».

## Ubuntu 20.04: что будет на практике

### MIME-тип `.md`

На Linux ассоциации идут не только по расширению, а по MIME. Для markdown обычно:

- `text/markdown`
- иногда `text/x-markdown` / `text/plain` (зависит от `shared-mime-info` и окружения)

Проверка у пользователя:

```bash
mimetype README.md
# или
xdg-mime query filetype README.md
```

Ожидаемо: `text/markdown`. В манифесте PWA лучше указать и MIME, и расширения.

### Как пользователь назначит приложение по умолчанию

После установки PWA:

1. ПКМ по `.md` → **Открыть с помощью…** → выбрать установленный web-app.
2. Поставить галку «Всегда» / через свойства файла в Nautilus (GNOME) или аналог.
3. Либо вручную:

```bash
xdg-mime default chrome-XXXX-Default.desktop text/markdown
xdg-mime query default text/markdown
```

Имя `.desktop` у PWA Chrome генерирует сам (часто `chrome-<id>-Default.desktop`).

**Важно:** сайт **не может** бесшумно стать дефолтным обработчиком всех `.md` без участия пользователя. Это ограничение безопасности ОС/браузера, не баг проекта.

### Permission prompt Chrome

При открытии файла через File Handling API Chrome показывает запрос разрешения на доступ к файлу. Пока пользователь не нажмёт Allow (или не заблокирует), каждый раз может быть friction. После явного Allow/Block решение сохраняется; при изменении `file_handlers` в манифесте права могут сброситься.

### Snap Chromium / песочница

На Ubuntu Chromium часто ставится как snap. Иногда это даёт странности с доступом к файлам и desktop-интеграцией. Для продакшн-сценария надёжнее тестировать на **Google Chrome (.deb)** и/или актуальном Chromium, а не полагаться только на snap без проверки.

### Десктопное окружение

Ubuntu 20.04 чаще всего GNOME. Сценарий «Открыть с помощью» работает, но UX менее «магический», чем на macOS/Windows в демо Chrome. Это не блокер, но нужно заложить в онбординг: короткая инструкция «как сделать приложением по умолчанию».

## Риски и ограничения концепции

### Высокий приоритет

1. **Зависимость от Chromium.** Без него «открытие всех `.md` из ОС» не выполняется.
2. **Не автоматический дефолт.** Фраза «теперь все файлы открываются» верна только после выбора пользователя.
3. **HTTPS и хостинг.** Для настоящей установки нужен сайт (или локальный HTTPS). «Просто папка с HTML» без сервера — не installable PWA.
4. **Браузер должен оставаться установленным.** PWA — не независимый бинарник; удалили Chrome — пропало приложение.

### Средний приоритет

5. **MIME/расширения.** Часть `.md` может определяться как `text/plain`; тогда ассоциация может не сработать. Нужно регистрировать несколько MIME и `.md`/`.markdown`.
6. **Относительные картинки и ссылки.** `![img](./a.png)` из локального файла без доступа к соседним файлам не откроется «как в редакторе». Для полноценного превью каталога нужен File System Access API (выбор папки) или отказ от локальных ассетов.
7. **Офлайн.** Возможен через service worker, но сам факт первого визита и обновлений зависит от сети (если нет offline-кэша).
8. **Безопасность рендера.** Markdown → HTML требует санитизации (XSS через HTML/скрипты в `.md`). Для viewer-only это обязательно.

### Низкий / продуктовый

9. Темы, GFM, математика, диаграммы — всё реализуемо, но это уже scope, не feasibility.
10. Несколько файлов / вкладки — решаемо через `launch_type` и UI.

## Что реализуемо легко

- Landing: «Установить приложение».
- Рендер CommonMark / GFM.
- Режим только чтения (нет `showSaveFilePicker`, нет записи).
- Открытие через UI: drag-and-drop, `<input type="file">`, «Недавние» (если хранить handles с permission).
- Offline shell после установки.
- Красивый viewer UX (типографика, тёмная/светлая тема, оглавление).

## Что реализуемо, но хрупко

- Системное «Open with» / default handler через PWA на Linux.
- Стабильность на snap-Chromium.
- Ожидание «как у нативного пакета из apt».

## Что концепцией «чистого сайта» не закрывается

- Полная независимость от браузера.
- Гарантированная работа во Firefox как системный handler.
- Тихий захват всех `.md` без подтверждения пользователя.
- Надёжный доступ ко всем соседним файлам репозитория без явного разрешения на папку.

## Альтернативы, если PWA окажется недостаточно удобной на Ubuntu

| Подход | Плюсы | Минусы |
|---|---|---|
| **PWA (рекомендуемый старт)** | Соответствует концепции «зашли на сайт → установили»; один кодбейс | Только Chromium для file handlers |
| **Tauri / Electron** | Настоящий `.desktop` + `MimeType=text/markdown;` | Это уже не «просто сайт», нужен дистрибутив |
| **Локальный helper + `.desktop`** | Точный контроль ассоциаций на Linux | Отдельная установка, сложнее UX |
| **Гибрид: PWA + инструкция xdg-mime** | Быстрый MVP | Ручной шаг для пользователя |

Для проверки концепции правильный порядок: **сначала PWA + Chrome на Ubuntu**, измерить UX открытия `.md`, и только потом решать, нужен ли native wrapper.

## Минимальный MVP для проверки гипотезы

Цель MVP — не идеальный viewer, а ответ на вопрос: *«двойной клик по `.md` открывает наш app и показывает HTML?»*

1. Статический сайт (Vite/vanilla) на HTTPS (или Cloudflare Pages / GitHub Pages).
2. Manifest с `display: "standalone"` и `file_handlers` для `.md`.
3. Service worker (минимальный).
4. `launchQueue` → `file.text()` → markdown-it → санитизация → DOM.
5. Fallback: drag-and-drop и кнопка «Открыть файл».
6. Короткая страница «Как сделать приложением по умолчанию на Ubuntu».
7. Тест-матрица:
   - Google Chrome на Ubuntu 20.04;
   - Chromium snap;
   - Firefox (ожидаемо: install/open-with неполное);
   - GNOME Files: Open With / Always.

Критерий успеха MVP:

- в Chrome PWA ставится;
- приложение появляется в «Открыть с помощью»;
- после выбора по умолчанию `.md` открывается в app;
- текст рендерится;
- записи на диск нет.

Если пункт «Open With» нестабилен именно на целевой машине — концепция в чистом PWA-виде для Ubuntu считается **частично проваленной**, и нужно рассматривать Tauri/Electron.

## Рекомендация

**Идти в реализацию как в PWA-viewer с Chromium-first стратегией.**

Обоснование:

- идея совпадает с официальными возможностями web platform;
- просмотр markdown не создаёт технических блокеров;
- главный неизвестный фактор — качество OS-integration на Ubuntu 20.04 + выбранный браузер пользователя;
- это дёшево проверить прототипом за небольшой объём работы.

Не обещать в маркетинге «работает в любом браузере как системный просмотрщик». Обещать:

> Установите как приложение в Chrome/Chromium — и открывайте `.md` двойным кликом.

Редактирование сознательно не делать: это упрощает безопасность, permissions и UX, и лучше соответствует заявленной цели.

## Краткий итог

- **Да, идея в целом реализуема** на Ubuntu 20.04.
- **Ключ успеха:** Chromium + PWA `file_handlers` + `launchQueue`.
- **Ключевой риск:** Firefox и/или слабая desktop-интеграция; «все файлы сами» только после назначения default app пользователем.
