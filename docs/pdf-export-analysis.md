# Анализ: экспорт Markdown → PDF в PWA (Markdown Viewer)

**Дата:** 2026-08-26  
**Контекст приложения:** Vue 3 PWA, клиентский рендер (`markdown-it` + DOMPurify + Mermaid), локальные `.md`, без бэкенда, GitHub Pages.  
**Вопрос:** можно ли реализовать экспорт в PDF **внутри** PWA и какими путями.

---

## Вердикт

**Да, экспорт в PDF в рамках PWA реализуем**, полностью на клиенте и без сервера.

Ограничение не в PWA как таковом, а в **качестве и типе PDF**:

| Ожидание | Реалистичность в чистом клиентском PWA |
|---|---|
| Кнопка «Экспорт PDF» → файл на диск | Высокая |
| Offline / без бэкенда | Высокая (при выборе клиентских методов) |
| PDF «как на экране», с Mermaid | Средняя–высокая (зависит от метода) |
| Выделяемый текст, поиск, копирование | Только у части методов |
| Идеальная вёрстка, колонтитулы, оглавление | Средняя; проще через print CSS или сервер |
| Тихий экспорт без UI браузера | Средняя (`window.print` всегда показывает диалог) |

**Итог:** для Markdown Viewer разумны два клиентских направления — **print → Save as PDF** (качество рендера) и **DOM → canvas → PDF** (один клик, но «картинка»). Серверные/облачные варианты дают лучший PDF, но ломают текущую модель «только локальный PWA на Pages».

---

## Что уже есть в приложении (релевантно для PDF)

- Готовый DOM документа: `.markdown-body` (HTML после sanitize).
- Mermaid уже рисуется в SVG внутри страницы — для экспорта важно **дождаться** `mermaid.run`, иначе схемы пропадут или обрежутся.
- Имя файла известно (`sample.md` → логично `sample.pdf`).
- Сохранение: File System Access API (`showSaveFilePicker`) в Chromium **или** обычный download через Blob + `<a download>`.
- PWA standalone: `window.print()` работает, но UX диалога зависит от ОС/браузера; в установленном приложении поведение обычно как в Chrome.

## Классы подходов

```text
Markdown (.md)
    │
    ├─ A. Print pipeline ──────────► browser print engine ──► PDF
    │     (то, что видит @media print)
    │
    ├─ B. Raster pipeline ─────────► html2canvas ──► jsPDF ──► PDF
    │     (страница как изображение(я))
    │
    ├─ C. Programmatic PDF ────────► pdfmake / jsPDF API ──► PDF
    │     (не HTML, а «сборка» из блоков)
    │
    └─ D. Headless / cloud ────────► Playwright / API ──► PDF
          (нужен сервер или внешний сервис)
```

## Библиотеки и инструменты

### Клиент (подходят PWA / offline)

| Инструмент | Что делает | Текст в PDF | CSS / Flex / таблицы | Mermaid SVG | Размер бандла (порядок) | Зрелость |
|---|---|---|---|---|---|---|
| **`window.print` + `@media print`** | Нативный диалог печати / «Сохранить как PDF» | Да | Лучший (движок браузера) | Да (как на экране) | 0 | Стандарт |
| **html2pdf.js** | Обёртка html2canvas + jsPDF | Нет (растр) | Ограничен html2canvas | Обычно да, как картинка | ~средне | Популярна, ограничения известны |
| **html2canvas + jsPDF** | То же вручную | Нет | Ограничен | Да при аккуратной подготовке | средне | Гибче html2pdf |
| **jspdf-html2canvas / html2canvas-pro** | Вариации растрового пайплайна | Нет | Ограничен | Аналогично | средне | Форки / аналоги |
| **jsPDF** (API: text, таблицы) | Ручная вёрстка PDF | Да | Нет HTML-вёрстки | Нужно отдельно вставлять SVG/PNG | меньше, если без canvas | Зрелая |
| **pdfmake** | Декларативные doc-definition | Да | Своя модель, не CSS | SVG/изображения вручную | средне | Зрелая |
| **pdf-lib** | Сборка/правка PDF на низком уровне | Да (если сами кладёте) | Нет | Вставка PNG/SVG вручную | средне | Хорош как «склейка», не как HTML→PDF |
| **dom-to-image / modern-screenshot** | Снимок DOM → PNG/SVG | — | Зависит | Часто лучше/хуже html2canvas точечно | меньше | Альтернатива растру |
| **md-to-pdf / markdown-pdf** | Обычно Node/CLI | Да | Через Puppeteer и т.п. | Через HTML | — | **Не для браузерного PWA** |
| **PDF.js (Mozilla)** | **Рендер уже готового PDF → canvas/DOM** | n/a (вход = PDF) | n/a | n/a | крупный | Зрелая, но **другая задача** |

#### Почему не PDF.js

**[PDF.js](https://mozilla.github.io/pdf.js/)** — библиотека **просмотра** PDF в браузере (парсит PDF и рисует страницы). Она **не умеет** «Markdown/HTML → PDF».

| Задача | PDF.js | Нужно нам |
|---|---|---|
| Открыть/показать `.pdf` | Да | Нет (у нас `.md`) |
| Сгенерировать PDF из HTML/Markdown | **Нет** | Да |
| Редактировать/собрать PDF | Нет (есть отдельные проекты вокруг) | Частично |

Путаница часто с **jsPDF** (генерация) и **PDF.js** (просмотр). Для экспорта из viewer остаются print / html2canvas+jsPDF / pdfmake и т.д. PDF.js имел бы смысл, только если позже появится «открыть чужой PDF рядом с md» — это отдельная фича, не экспорт.

### Сервер / облако (не «чистый» Pages-PWA)

| Инструмент | Плюсы | Минусы для нашего проекта |
|---|---|---|
| **Playwright / Puppeteer** | Качество ≈ Chrome print | Нужен backend, хостинг, стоимость |
| **Gotenberg, WeasyPrint, Prince** | Хорошая типографика | Инфраструктура / лицензии |
| **Cloud HTML→PDF API** | Быстрый старт качества | Данные уходят с машины; противоречит «локальные файлы» |

## Варианты реализации для Markdown Viewer

### Вариант 1 — Print CSS + `window.print()` (рекомендуемый MVP)

**Идея:** кнопка «Печать / PDF» → скрыть chrome UI через `@media print` → `window.print()` → пользователь выбирает «Сохранить как PDF».

**Плюсы**
- Максимальное визуальное сходство с экраном (шрифты, таблицы, Mermaid SVG).
- Выделяемый текст, нормальные ссылки в PDF (зависит от браузера).
- Нулевой вес зависимостей, offline из коробки.
- Хорошо стыкуется с PWA.

**Минусы**
- Всегда диалог печати (не «тихий» save).
- UX чуть менее «экспорт одной кнопкой».
- Нужна аккуратная print-вёрстка: поля, разрывы страниц, скрытие topbar/source/lightbox.

**Трудоёмкость:** **S — 0.5–1.5 дня**  
(кнопка, `@media print`, проверка Mermaid/длинных таблиц, ручной QA на Chrome/Edge/Linux).

**Риски:** низкие. В standalone PWA диалог печати доступен; на редких WebView — проверить.

---

### Вариант 2 — html2pdf.js / html2canvas + jsPDF (кнопка «Скачать PDF»)

**Идея:** снять `.markdown-body` (или клон с print-стилями) в canvas, нарезать на страницы A4, сохранить Blob как `.pdf` (download или `showSaveFilePicker`).

**Плюсы**
- Один клик без диалога печати.
- Полностью клиентски, offline после precache.
- Имя файла контролируем (`report.pdf`).

**Минусы**
- PDF ≈ набор картинок: нет нормального выделения текста, больше вес файла.
- html2canvas плохо дружит со сложным CSS, шрифтами, иногда с SVG.
- Длинные документы: память, время, артефакты на стыках страниц.
- Mermaid: нужно клонировать уже отрисованный SVG; lazy-chunk Mermaid в бандле PDF не участвует, но рендер должен завершиться до снимка.

**Трудоёмкость:** **M — 2–4 дня**  
(+1–2 дня полировки page-break / DPI / больших схем).

**Риски:** средние (качество на реальных документах). Бандл +1–2 MB gz без tree-shaking на весь html2pdf — желателен lazy `import()`.

---

### Вариант 3 — Гибрид: Print как основной + «Скачать PDF» как опция

**Идея:** в UI два действия или одно меню: «Печать / PDF…» (вариант 1) и «Скачать PDF» (вариант 2).

**Плюсы:** закрывает разные UX-ожидания; print даёт качество, download — удобство.  
**Минусы:** две кодовые ветки, двойной QA.  
**Трудоёмкость:** **M — 3–5 дней**.

---

### Вариант 4 — Программный PDF из AST Markdown (pdfmake / jsPDF)

**Идея:** не печатать HTML, а маппить токены markdown-it → абзацы/заголовки/таблицы pdfmake; Mermaid → SVG/PNG → image в PDF.

**Плюсы:** текст выделяемый; предсказуемые поля/шрифты; меньше сюрпризов html2canvas.  
**Минусы:** фактически второй рендерер; HTML/CSS приложения не переиспользуются; много работы на GFM-таблицы, code blocks, списки, картинки.  
**Трудоёмкость:** **L — 1.5–3 недели** до паритета с текущим viewer.  
**Для MVP нецелесообразно**, если цель — «как на экране».

---

### Вариант 5 — Серверный headless (Playwright) или cloud API

**Идея:** отправить HTML или `.md` на сервис → получить PDF.

**Плюсы:** лучшее качество «документа».  
**Минусы:** нужен backend; локальные файлы покидают устройство (или нужен self-host); не укладывается в текущий GitHub Pages-only деплой без отдельного сервиса.  
**Трудоёмкость:** **L — 1–2+ недели** (инфра + безопасность + квоты).  
**Рекомендация:** только если появится требование «корпоративный PDF» и допустим сервер.

## Особенности Mermaid и PWA

1. **Экспортировать нужно уже отрисованный SVG**, не исходный ` ```mermaid `.
2. Перед экспортом: дождаться `mermaid.run`, скрыть кнопки «На весь экран» / lightbox в print или в клоне DOM.
3. Широкие схемы: в print — `max-width: 100%` / landscape опционально; в html2canvas — scale 2–3, осторожно с памятью.
4. Service Worker: PDF-библиотеки лучше **lazy-import**, иначе precache раздувается (у нас уже лимит workbox ~1.5 MB на файл; Mermaid и так крупный).
5. Сохранение: в Chromium PWA предпочтителен `showSaveFilePicker({ suggestedName })`, fallback — `<a download>`.

## Рекомендуемый план

### Фаза A — MVP (быстро, высокое качество)

1. Кнопка «Экспорт / Печать PDF» в topbar (только когда файл открыт).
2. `@media print`: скрыть topbar, welcome, drop-overlay, source panel chrome, mermaid toolbar; оставить `.markdown-body`.
3. `window.print()`.
4. Краткая подсказка в UI: «В диалоге выберите „Сохранить как PDF“».

**Оценка:** ~0.5–1.5 дня.

### Фаза B — по потребности

1. Lazy `html2pdf` / html2canvas+jsPDF → «Скачать PDF».
2. Клон DOM без UI-кнопок, `pagebreak`, filename из текущего `.md`.
3. Тесты на fixture с Mermaid + длинной таблицей; ручной визуальный чеклист.

**Оценка:** +2–4 дня.

### Не делать сейчас

- Серверный Playwright «ради PDF», пока нет бэкенда.
- Полный AST→pdfmake, пока print/html2pdf не упрётся в потолок качества.

## Оценка трудоёмкости (сводка)

| Вариант | Оценка | Когда выбирать |
|---|---|---|
| **1. Print CSS + window.print** | **0.5–1.5 дн** | MVP, лучшее качество «как на экране» |
| **2. html2pdf / html2canvas+jsPDF** | **2–4 дн** | Нужен прямой download без диалога печати |
| **3. Гибрид 1+2** | **3–5 дн** | Хотим оба UX |
| **4. pdfmake/jsPDF из AST** | **1.5–3 нед** | Жёсткие требования к текстовому PDF и кастомной вёрстке |
| **5. Server/cloud** | **1–2+ нед + инфра** | Корпоративное качество и допустим backend |

*Оценки — для одного разработчика, знакомого с текущим репо; без учёта полировки «идеальной» типографики всех edge-case Markdown.*

## Риски и ограничения (чеклист)

- [ ] Диалог печати нельзя полностью убрать в браузере (политика безопасности).
- [ ] Растровый PDF плохо масштабируется и тяжелее по размеру.
- [ ] html2canvas: известные баги с `oklch`/новыми CSS, внешними шрифтами, overflow.
- [ ] Очень большие `.md` + много Mermaid → риск OOM на слабых машинах при canvas.
- [ ] Firefox/Safari: File System Access для save ограниченнее; download fallback обязателен.
- [ ] Продуктовая позиция «только чтение локальных файлов» сохраняется: экспорт — **новый** файл, исходный `.md` не меняем.

## Вывод

Экспорт PDF **вписывается в текущую PWA-архитектуру**.  

**Практичный путь:** начать с **варианта 1 (print → Save as PDF)** — минимум кода, лучший рендер включая Mermaid. Если понадобится именно «Скачать PDF» одним кликом — добавить **вариант 2** ленивой загрузкой. Серверные решения оставлять на случай смены продуктовых ограничений (появление backend и согласия на отправку содержимого).
